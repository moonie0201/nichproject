# investiqs.net — 애드센스 심사관 관점 사이트 전체 재점검

조사일: 2026-09-01 (실제 접속 확인, curl + render_page 기반)

## 요약 (결론부터)

가장 큰 문제는 콘텐츠 품질이 아니라 **사이트 구조 자체가 "실체 없음"을 자백하고 있다**는 것이다.
심사관이 홈페이지에 도착해 상단 메뉴를 클릭하는 첫 30초 안에 **깨진 링크(404)**를 만나고,
전체 글은 13편뿐인데 그중 3편은 어떤 내비게이션에서도 도달 불가능한 고아 페이지다.
"가치가 별로 없는 콘텐츠"라는 거절 사유는 개별 글의 품질(69/100, 준수함) 문제가 아니라
**사이트 전체 규모·탐색 구조·운영 실체 신호**의 문제일 가능성이 높다.

---

## 1. 확인된 사실 (실제 접속 결과)

### 1-1. 🔴 헤더 내비게이션의 "시황" 메뉴가 404 — 홈페이지에서 즉시 발견됨
- 모든 페이지(홈 포함) 상단 메뉴에 `계산기 / 투자공부 / 시황` 3개 항목이 있음.
- `https://investiqs.net/ko/market/` → **HTTP 404** (`<div class=not-found>404</div>`).
- 홈페이지 HTML(`/ko/`)에 이 링크가 직접 박혀 있음: `href=https://investiqs.net/ko/market/`.
- 즉 **모든 방문자가 홈에 도착하자마자 볼 수 있는 3개 메인 메뉴 중 1개가 죽은 링크**다.
- 애드센스 심사관은 정확히 이런 걸 찾는다: "이 사이트가 관리되고 있는가?"에 대한 직접적 부정 신호.
- **가장 시급한 수정 사항. 원인 파악 후 즉시 고치거나 메뉴에서 제거해야 함.**

### 1-2. 실제 발행 글은 13편, 그중 3편은 내비게이션으로 도달 불가능한 고아 페이지
- `/ko/study/` (투자공부): 게시물 10편 (article 태그 카운트로 직접 확인).
- `/ko/blog/`: 게시물 3편 (연말정산, 종합소득세, 연금저축 관련 세금 글).
- **`/ko/blog/`는 헤더 메뉴 어디에도 링크가 없다.** 홈페이지 HTML에도 `/ko/blog/`로 가는 링크가 전혀 없음(직접 확인, grep 결과 0건).
- 즉 일반 방문자가 홈 → 메뉴 클릭만으로 도달 가능한 글은 **study의 10편뿐**이고, blog의 3편은 사이트맵 URL을 직접 알아야만 찾을 수 있다.
- 실질적으로 "탐색 가능한 콘텐츠"는 10편 + 계산기 10개뿐이라고 봐야 한다.

### 1-3. 홈페이지(`/ko/`) — 3분간 훑어볼 때 보이는 것
- 전체 텍스트 125단어. 히어로 카피 2줄 + "인기 투자 도구" 카드 + "최신 분석" 글 4~5편 제목/요약 뿐.
- 스크롤해도 그 이상 나오지 않음(홈 HTML 16KB 중 실텍스트 비중 매우 낮음, 나머지는 CSS/스크립트/메타).
- "최신 분석" 아래 "더 보기"류 링크는 `/ko/study/`로 가지만, 홈 자체에 아카이브·카테고리·소개 요약 등 사이트 규모를 짐작케 할 요소가 없음.
- **첫인상은 "블로그"라기보다 "랜딩페이지 + 위젯 몇 개"에 가깝다.**

### 1-4. `/ko/tools/` (계산기 10개) — "콘텐츠"인가 "빈 위젯"인가
- 페이지 자체 텍스트는 266단어. 계산기마다 1~2문장 설명이 붙어 있음 (예: "ETF 수수료 비교 계산기 — 운용보수 차이의 장기 효과 — 두 ETF의 운용보수 차이가 장기 복리 수익에 미치는 영향을 시각화합니다...").
- 설명 문구는 존재하지만 **모두 1~2문장 수준의 기능 소개**이지, 계산 방법론·근거 데이터 출처·예시 시나리오 같은 깊이는 없음(목록 페이지 기준. 개별 계산기 페이지는 미확인이나, 목록에서 보이는 깊이는 이 정도).
- 결론: 완전히 빈 위젯은 아니지만, "고유하고 깊이 있는 콘텐츠"로 보기도 어렵다. **텍스트 콘텐츠보다 기능(계산기 자체)이 주가 되는 유틸리티 페이지**로 읽힐 가능성이 크다. 계산기 10개를 "10편의 콘텐츠"로 카운트하면 심사관 눈엔 과대평가로 보일 위험이 있다.

### 1-5. 태그·카테고리 아카이브 — robots.txt로 막았지만 여전히 존재하고 접근 가능
- `robots.txt`: `Disallow: /tags/`, `/categories/`, `/*/tags/`, `/*/categories/` (User-agent: * 대상, Googlebot 포함).
- 단, **GPTBot / ClaudeBot / PerplexityBot / Google-Extended는 명시적으로 Allow** — AI 크롤러는 이 페이지들을 볼 수 있음.
- 직접 접속 시 `/ko/tags/`, `/ko/categories/` 모두 HTTP 200 정상 응답.
- 태그 목록을 보면 **1건짜리 태그가 압도적으로 많음** (AGG=1, BND=1, DCA=1, DRIP=1, ELN=1, QLD=1, TQQQ=1, VIG=1 등 수십 개). 즉 "글 1편당 태그 1개짜리 아카이브 페이지"가 대량으로 존재하는 구조.
- 예시로 확인한 `/ko/tags/agg/` 페이지: 게시물 1편의 발췌문만 재노출하는 100단어짜리 페이지. 원문 글과 사실상 중복 콘텐츠.
- 카테고리 중에는 **"자동생성"이라는 이름의 카테고리가 실존**하며 (`/ko/categories/자동생성/`), 여기 글 2편이 분류돼 있음. 접속해서 확인함 — 실제로 존재하고 200 응답.
- 다행히 **이 페이지들은 사이트 어느 곳에서도 링크되지 않은 고아 페이지**(홈/글 본문/푸터 어디에도 `/tags/`, `/categories/` 링크 없음, grep으로 확인)이므로 일반 방문자나 Googlebot이 자연스럽게 마주칠 가능성은 낮음. 다만 URL을 안다면(사이트맵에는 없지만 Hugo가 자동 생성) 여전히 접근 가능하고, AI 크롤러는 robots 예외로 인해 이 얇은 중복 페이지들을 그대로 수집한다.
- **애드센스 심사 자체에는 낮은 위험**(로봇 차단 + 링크 없음)이지만, "자동생성"이라는 노출된 카테고리명은 만약 심사관이 URL 추측이나 site: 검색으로 우연히 발견하면 즉각적으로 나쁜 인상을 줄 수 있는 요소다.

### 1-6. AI 투명성 공개 페이지 (`/ko/about/authors/`) — 심사관에게 어떻게 읽히는가
- 푸터 → "소개"(`/ko/about/`) → 본문 링크로 `/ko/about/authors/` 2클릭 이내 도달 가능. 실제로 링크 확인함.
- 내용 그대로 인용: *"InvestIQs의 모든 분석 글, 시장 요약, 영상 스크립트는 대규모 언어 모델(LLM)을 사용해 자동 생성됩니다. 사람 애널리스트가 한 줄 한 줄 작성한 것이 아닙니다."*
- 사용 모델까지 구체적으로 명시(Claude Haiku 4.5/Sonnet 4.6, Gemini 등).
- 모든 글의 바이라인은 예외 없이 **"InvestIQs Research"** — 실명, 사진, 약력, 자격증, LinkedIn 등 개인 저자 정보가 사이트 어디에도 없음(about, authors, contact 페이지 모두 확인, 개인 신원 정보 전무).
- **Sept 2025 QRG 기준으로 AI 콘텐츠 자체는 허용되지만, 이 페이지는 "낮은 노력, 독창성 없음, 대량 생성"으로 스스로를 규정하는 문구**(자동 생성, 사람 검수자가 모든 글을 검토하지 못함, 룰 기반 자동 거부 등)를 담고 있다.
- 투자(YMYL) 분야에서 **실명 전문가/저자 신원이 전무한 상태 + "우리는 사람이 안 씀"이라는 자기 고백**이 결합되면, 심사관 입장에선 "낮은 노력 AI 콘텐츠" 신호로 오독될 소지가 실제로 있다. 특히 이 페이지가 있다는 사실 자체보다, **13편이라는 얇은 볼륨과 결합됐을 때** 더 부정적으로 읽힐 가능성이 있다(콘텐츠가 많고 다양하면 이 공개는 오히려 신뢰 신호가 될 수 있지만, 13편뿐이면 "AI가 조금 만들고 투명성만 내세운다"는 인상으로 반전될 수 있음). 이 부분은 **추정**이며 확정적 사실은 아니다.

### 1-7. 개별 글 품질 자체는 확인상 문제 없음 (참고)
- 예: `/ko/study/etf-distribution-health-insurance-dependent-2026/` — 1,175단어, 발행일 2026-07-29, 구체적 수치·법령 인용 포함.
- 기존 감사(69/100)와 일치하는 수준. 이번 조사에서도 개별 글 품질 자체를 뒤집을 근거는 발견하지 못함.

## 2. 요청받은 질문에 대한 답

### Q1. 기사 15편(정정: 실측 13편) + 계산기 10 + 유틸 13 = 38 URL 규모가 애드센스 기준으로 충분한가
- **애드센스는 공식적으로 "URL 개수" 최소 기준을 발표하지 않는다.** 다만 실무적으로 반복 거절 사례들은 대개 "탐색 가능한 고유 콘텐츠가 체감상 부족하다"는 패턴과 함께 온다.
- 이번 조사의 핵심은 개수 자체보다 **"실제 방문자가 자연 탐색으로 도달 가능한 콘텐츠"가 사이트맵 숫자(38)보다 훨씬 적다**는 것: `/ko/blog/`(3편)는 내비게이션에서 링크되지 않고, `/ko/market/`은 404다. 즉 심사관이 실제로 클릭해서 만나는 콘텐츠는 **study 10편 + 계산기 10개 + about류 몇 페이지** 정도로, 사이트맵상 38개보다 체감 규모가 더 작다.
- 결론: 38이라는 숫자 자체보다, **"보이는 것"과 "존재하는 것"의 불일치**(고아 페이지, 죽은 링크)가 규모를 실제보다 더 빈약해 보이게 만들고 있다.

### Q2. 계산기 페이지가 "고유 콘텐츠"로 인정될 만한가, 얇은 페이지로 카운트될 위험이 있는가
- 목록 페이지(`/ko/tools/`) 기준으로 각 계산기는 1~2문장 설명만 있고, 계산기 자체가 페이지의 주된 가치다.
- 애드센스 심사에서 계산기/툴 페이지는 "기능은 있으나 텍스트 콘텐츠가 얇은 페이지"로 분류될 위험이 실제로 있다. 10개 계산기를 "10편의 콘텐츠"처럼 사이트 규모에 합산해 온 것은 **과대평가일 가능성**이 있다. (개별 계산기 페이지 본문 깊이는 이번 조사에서 미확인 — 목록 페이지 수준의 설명 깊이만 확인함. 개별 페이지에 방법론·FAQ·예시가 충분히 있다면 이 우려는 완화된다.)

### Q3. AI 투명성 공개가 심사관에게 어떻게 읽히는가
- 위 1-6 참조. **결론: 양날의 검.** 콘텐츠가 풍부하고 검증 프로세스가 신뢰할 만하면 투명성은 가산점이 될 수 있지만, 지금처럼 사이트 볼륨이 작고 실명 저자가 전혀 없는 상태에서는 "AI가 대량으로 찍어낸 사이트"라는 기존 우려를 심사관 스스로의 언어로 확인시켜주는 역효과를 낼 수 있다. 이는 추정이다.

### Q4. 축소(896편 → 15편, 실측 13편)가 오히려 해가 됐다는 근거가 있는가
- 직접적 인과관계를 증명할 근거는 없다(2차 거절 사유가 "가치가 별로 없는 콘텐츠"로 1차와 동일했다는 사실 외에는 축소 전후 비교 데이터가 없음).
- 다만 이번 조사로 확인된 것은: **축소 자체가 문제라기보다, 축소 이후 남은 리소스의 내비게이션/구조 정합성을 재검증하지 않은 것**이 문제로 보인다. 즉 대량 삭제 과정에서 `/ko/market/` 메뉴가 가리키던 콘텐츠(예: market wrap 관련 페이지)가 삭제되면서 메뉴만 남아 404가 된 것으로 추정된다(정황 증거: 메뉴명 "시황"과 CLAUDE.md에 기록된 `us_market_wrap`/`market` 관련 자동화 파이프라인이 존재함 — 실제 원인은 코드/배포 이력 확인 필요, 이번 조사에서는 URL 접속 결과만 확인함).
- **"콘텐츠가 부족해서"보다 "콘텐츠는 있는데 찾아갈 길이 끊겨 있고, 메뉴가 거짓말을 하고 있어서"일 가능성**을 진지하게 검토해야 한다.

## 3. 우선순위 권고 (실행 순서)

1. **[즉시] `/ko/market/` 404 수정** — 콘텐츠를 복구하거나, 안 되면 메뉴에서 해당 항목 자체를 제거. 죽은 내비게이션 링크는 애드센스 심사 이전에 기본적인 사이트 위생 문제.
2. **[즉시] `/ko/blog/`를 헤더 메뉴에 노출** — 지금은 발행된 3편이 사실상 존재하지 않는 것과 같음. `투자공부`와 통합하든, 별도 메뉴 항목을 추가하든 방문자가 도달 가능하게 해야 함.
3. **[검토] 태그/카테고리 아카이브 정리** — "자동생성" 같은 카테고리명 변경 또는 삭제, 1건짜리 태그 대량 생성 방지(Hugo 설정에서 taxonomy 최소 게시물 수 미만이면 페이지 생성 안 하도록 조정 검토).
4. **[검토] 저자 신뢰 신호 보강** — 최소 1명이라도 실명 검수자/편집장 정보를 추가하거나, 최소한 "왜 실명 저자가 없는지"에 대한 설명을 지금보다 신뢰감 있게 보강. YMYL 콘텐츠에서 이 공백은 계속 리스크로 남는다.
5. **[선택] 계산기 페이지 본문 보강** — 목록 설명 외에 개별 계산기 페이지에 방법론/FAQ/예시 시나리오가 충분한지 별도 확인 필요(이번 조사 범위 밖).

## 4. 조사 방법 메모
- 모든 URL은 `curl`(HTTP 상태 코드) 및 `render_page.py --mode never`(추출 텍스트)로 실접속 확인.
- HTML 원본을 직접 파싱해 내비게이션 링크, 사이트맵, robots.txt를 교차 검증.
